**1. Временное окно и качество данных.**

Дата публикации `D` фиксируется один раз в `Europe/Moscow`.

| Период | Часы |
|---|---|
| Утро | D 06–11 |
| День | D 12–17 |
| Вечер | D 18–23 |
| Ближайшая ночь | D+1 00–05 |

Каждый период содержит шесть ожидаемых часовых интервалов. Используются полные даты, сортировка по времени и проверка дубликатов. Конфликтующие записи одного часа не выбираются произвольно.

Отсутствующее поле, некорректное значение и ноль различаются. Неизвестные значения не восстанавливаются из соседнего часа. Ночь начала `D` не подставляется вместо ночи `D+1`.

**2. Категория, преобладание и кратковременные явления.**

`condition.code` определяет категорию, русский текст, интенсивность и признаки опасности через единый справочник. `condition.text` не управляет результатом.

Для полного периода:

- Категория, занимающая минимум четыре часа, считается преобладающей.
- Разные интенсивности одного типа осадков объединяются при подсчёте продолжительности, сохраняя интенсивность каждого часа.
- При отсутствии преобладания описывается смена погоды.
- Числовые коды не усредняются.
- Кратковременные осадки не теряются среди сухих часов.
- Потенциально опасное явление сохраняется независимо от преобладания.

| Согласованный эпизод осадков | Формулировка |
|---|---|
| Один эпизод на 1–2 часа | «кратковременно» |
| 3–4 часа либо несколько раздельных эпизодов | «временами» |
| Непрерывный эпизод на 5–6 часов | «продолжительный» |

Пропуск данных разрывает эпизод. Для возможных осадков обязательно сохраняется слово «возможен/возможны»; их продолжительность не представляется установленной.

**3. Вероятность, количество и снегопад.**

Вероятность, количество и интенсивность оцениваются отдельно.

| Вероятность | Редакционная интерпретация |
|---|---|
| Менее 30% | Низкая вероятность |
| 30–69% | «Возможен/возможны» |
| От 70% | Поддерживает «ожидается» при согласованных данных |
| Отсутствует | Вероятность неизвестна |

Для периода сохраняется максимум почасовой вероятности отдельно по дождю и снегу. При выводе процентов используется «в отдельные часы до …%». Это не вероятность события за весь период.

`precip_mm` и `snow_cm` суммируются отдельно. Количество повторно на вероятность не умножается; миллиметры не переводятся в сантиметры снега постоянным коэффициентом. При пропусках сумма маркируется как неполная.

Правила интерпретации снега:

| Данные | Решение |
|---|---|
| Снежный код, высокая вероятность, положительное количество | Согласованный прогноз снега |
| Снежный код и положительный `snow_cm`, вероятность отсутствует | Снег поддержан количественными данными; проценты неизвестны |
| Снежный код, количества отсутствуют | Количество неизвестно |
| Только повышенная вероятность снега | «Возможен снег» |
| Сильный снежный код, нулевая вероятность и нулевые количества | Осторожное «возможен снег», без утверждения силы |
| Дождевой код и положительный `snow_cm` | Тип осадков неоднозначен |
| Минусовая температура и положительный `precip_mm` | Недостаточно оснований назвать осадки снегом |

**Слово «сильный» в предупреждении о снеге допускается только при совокупности условий:**

- код предусматривает сильный снег;
- `chance_of_snow ≥ 30%`;
- в соответствующем часе положительны и `snow_cm`, и `precip_mm`;
- отсутствует конфликт типа осадков.

При вероятности 30–69% — «возможен сильный снег», от 70% — «ожидается сильный снег». Неоднозначный код «умеренный или сильный» не превращается в однозначное утверждение силы.

Положительное количество подтверждает осадки, но само по себе не доказывает сильную интенсивность: её источником остаётся код поставщика. Собственные количественные нормативы сильного снегопада в 1.1 не вводятся.

Если подтверждений недостаточно:

- пользовательский текст: «возможен снег»;
- без `⚠️`, если нет другого подтверждённого опасного явления;
- без фраз «интенсивность неясна» или «данные противоречивы»;
- причины и исходные значения сохраняются в диагностике.

Один сильный час не распространяется на весь период. Перенос снега ветром и метель не считаются автоматически новым снегопадом.

**4. Ледяной дождь.**

Freezing rain и freezing drizzle остаются отдельными категориями. Обычный дождь при минусовой температуре самостоятельно в них не переклассифицируется.

`chance_of_rain` используется как дополнительный сигнал дождя, а не как отдельная вероятность ледяного дождя.

| Данные | Пользовательская формулировка |
|---|---|
| Freezing-код, высокая вероятность дождя, положительный `precip_mm` | «Ожидается ледяной дождь» |
| Freezing-код, вероятность или количество отсутствуют | «Возможен ледяной дождь» |
| Freezing-код, нулевая вероятность и нулевое количество | «Возможен ледяной дождь» |
| Только минусовая температура и дождь | Без самостоятельного объявления ледяного дождя |

Даже кратковременный возможный ледяной дождь получает `⚠️`. Это предупреждение о потенциальном опасном типе осадков с явной неопределённостью, а не подтверждение интенсивности.

Технические расхождения сохраняются в диагностике. Пользовательский комментарий может содержать «возможно обледенение», но не утверждает уже образовавшийся гололёд.

**5. Компактная температура периода.**

Используются пригодные почасовые `temp_c`.

1. Рассчитываются исходные минимум и максимум.
2. Если их разность **не менее 3 °C**, выводится диапазон.
3. При меньшем разбросе выводится медиана.
4. Для чётного числа значений медиана — среднее двух центральных значений отсортированного списка.
5. Округление до целого: половина от нуля. Отрицательный ноль заменяется на `0°`.

Порог проверяется **до округления**.

Примеры:

| Значения | Отображение |
|---|---|
| 8, 9, 10, 10, 9, 9 | `+9°` |
| 8, 9, 10, 11, 10, 9 | `+8…+11°` |
| −3, −2, −2, −1, −2, −2 | `-2°` |

Для агрегированного значения нужно минимум четыре пригодные температуры. При меньшем количестве температура периода не уточняется. `feelslike_c` её не заменяет.

**6. Ветер, порывы и рекомендации по одежде.**

| Показатель | Роль |
|---|---|
| Ветер от 20 до 30 км/ч | Кандидат для комментария: «заметный ветер» |
| Ветер от 30 км/ч | Повышенный приоритет: «сильный ветер» |
| Порывы от 30 км/ч | Отдельный кандидат для комментария |
| Порывы от 40 км/ч | Повышенный приоритет: «сильные порывы» |

Порывы не подменяют устойчивый ветер. Эти пороги не дают оснований для слов «шторм» или «ураган».

Рекомендация по одежде формируется из совпадающих по времени факторов:

| Сочетание | Допустимая рекомендация |
|---|---|
| Температура или ощущаемая температура не выше нуля | Тёплая одежда |
| `temp_c ≤ 8` и `feelslike_c ≤ 5` | Тёплый дополнительный слой |
| Холод плюс ветер или сильные порывы | Тёплая непродуваемая одежда |
| Дождь плюс ветер/порывы | Защита от дождя с капюшоном |
| Холод, дождь и ветер одновременно | Тёплая непромокаемая одежда с капюшоном |
| Ветер от 20 км/ч без холода и осадков | Допустимо только упоминание ветра, без совета о куртке |

Для общего совета на период сочетание должно присутствовать хотя бы два последовательных часа. Совет для короткого эпизода допускается только с временным уточнением.

Отсутствующий `feelslike_c` не вычисляется. Известная отрицательная температура воздуха сама по себе остаётся основанием для тёплой одежды.

Фраза «по ощущениям холоднее» становится кандидатом при разнице минимум 5 °C в течение двух последовательных часов. Совет не должен объединять несвязанные события, например утренний ветер и вечерний дождь.

**7. `is_day` и температурные аномалии.**

Для солнечных и лунных значков используются только переданные WeatherAPI значения `is_day`.

- Для сводного значка берётся большинство значений среди часов соответствующей категории.
- При равенстве используется флаг центрального по времени часа; для чётного числа — второго из двух центральных.
- Нужно минимум четыре пригодных флага.
- При недостатке `is_day` солнечный/лунный значок опускается.
- Час суток, название периода и месяц не заменяют `is_day`.

Поэтому светлый летний вечер может получить `☀️`, а тёмный зимний — `🌙`.

Температурный скачок диагностируется при изменении `temp_c` **на 6 °C и более между соседними часовыми записями с интервалом ровно один час**.

Сохраняются времена, значения, разность и причина `TEMP_JUMP`. Скачок:

- не исправляется и не сглаживается;
- не исключается автоматически из минимума, максимума или медианы;
- сам по себе не становится пользовательским предупреждением;
- через пропуск часов не рассчитывается как часовой.

**8. Неполные периоды, приоритеты и длина.**

Полнота отдельно учитывается для категорий, температуры, количеств и `is_day`.

- При 4–5 пригодных часах разрешена ограниченная сводка с отметкой `[4/6 ч]` или `[5/6 ч]`.
- При 0–3 часах — «данных недостаточно».
- Опасное явление в доступных часах сохраняется с соответствующим уточнением.
- Частичный период не называется полностью сухим или продолжительно дождливым.
- Неизвестная температура не запрещает показать известное условие.
- Отсутствующая следующая ночь не подменяется другой датой.

Приоритет полного сообщения:

1. Ледяной дождь и другие потенциально опасные явления.
2. Подтверждённые сильные осадки.
3. Продолжительные осадки.
4. Сильный ветер и порывы.
5. Ощущаемый холод.
6. Кратковременные обычные осадки.
7. Заметный ветер и нейтральное описание.

Противоречивый сильный снежный код сам по себе не получает приоритет подтверждённого сильного снегопада.

Полное сообщение ограничивается **1024 единицами UTF-16**, включая переносы и эмодзи. Комментарий — до 180 единиц, максимум два предложения.

Сокращаются дополнительные пояснения, второстепенные численные детали и оформление. Сохраняются дата, следующая ночь, опасные явления, слова вероятности и кратковременности, отметки неполноты. Произвольное обрезание текста запрещено. Для предельных случаев требуется заранее проверенный компактный шаблон.

**9. Фотосценарий и fallback.**

Фотография относится к текущему дню D 06–23.

Порядок выбора:

1. Freezing rain, существенный конфликт осадков или неизвестная дневная погода → без фотографии.
2. Согласованный снег от трёх часов либо отдельный подтверждённый сильный снег → `snowy`.
3. Согласованный дождь от трёх часов → `rainy`.
4. Кратковременный или возможный обычный дождь → `small_rain_possible`.
5. Без приоритетных осадков сильный ветер или порывы → `strong_wind`.
6. Затем температурные и обычные сценарии: `cold`, `sunny_warm`, `cloudy_comfortable` и другие существующие ключи.

Ночной снег следующего дня не выбирает дневную снежную фотографию.

Сохраняются `PHOTO_SEASON`, архив, одобрение и проверка хеша. Отсутствие подходящей фотографии означает текстовую публикацию.

Неизвестный код получает нейтральное описание и `❔`. Технические причины не попадают в пользовательский текст. Неверная дата либо полностью непригодный дневной прогноз останавливают подготовку до отправки.

**10. Синтетические сценарии и эталонный текст.**

Это искусственные входы, не историческая погода.

По умолчанию `D=04.11.2026`; каждый период содержит шесть часов. Исходно все четыре периода равны `A = O(10)×6`. Неуказанные значения: ветер 10 км/ч, порывы 15 км/ч, `feelslike_c=temp_c`. Поля `will_it_*` отсутствуют.

| Час | Код | Вероятности дождя/снега | Количества |
|---|---:|---|---|
| `O(t)` | 1006 | 0 / 0 | 0 мм / 0 см |
| `C(t)` | 1000 | 0 / 0 | 0 мм / 0 см |
| `R(t,p,m)` | 1183 | p / 0 | m мм / 0 см |
| `S(t,p,s,m)` | 1213 | 0 / p | m мм / s см |
| `H(t,p,s,m)` | 1225 | 0 / p | m мм / s см |
| `F(t,p,m)` | 1198 | p / 0 | m мм / 0 см |
| `U(t)` | 9999 | 0 / 0 | 0 мм / 0 см |
| `?` | Час отсутствует | Неизвестны | Неизвестны |

Для обычных примеров переданные флаги `is_day`: утро и день — шесть единиц, вечер и ночь — шесть нулей. Это заданные входные данные, а не правило вычисления флага.

Эталонные комментарии ниже — детерминированный вариант. LLM не является условием приёмки.

```text
Вечер: +10° · облачно ☁️
Ночь 05.11: +10° · облачно ☁️
```

**11. Проверка внутренней согласованности.**

На уровне контракта устранены следующие противоречия:

- Сильный снежный код больше не означает автоматическое предупреждение о сильном снеге.

- Ветер 20 км/ч не означает автоматическую рекомендацию куртки.
- Ночной снег может быть главным событием комментария, но не выбирает дневную фотографию.
- Отсутствующие данные не улучшают полноту и не уменьшают вероятность осадков.
- Температурная аномалия не скрывается медианой, когда исходный разброс требует диапазона.
- `is_day` влияет на значок, но не меняет принадлежность часа к периоду.
- Сокращение сообщения не удаляет признаки вероятности или опасности.

Это проектная проверка. Автоматические тесты и измерение полного сформированного сообщения ещё не выполнялись.
