# Zvenigorod Weather Bot

Бот получает прогноз WeatherAPI для Звенигорода и публикует его с фотографией
в Telegram и MAX. Комментарий может генерировать OpenAI API: короткий,
доброжелательный комментарий с практичным советом на день.
Ответ — один абзац из одного-двух коротких предложений, до 180 символов.
Тон спокойный и заботливый, без обращения к читателю. Числа температуры,
ветра и вероятности осадков остаются в основном прогнозе.
Советы по одежде и зонту добавляются, когда полезны; совет на день — всегда.
Позитивный настрой создаётся через доступный приятный план, включая занятия
дома при непогоде, без пустых пожеланий и преуменьшения погодных рисков.
При ветре от 30 км/ч модель должна явно отметить сильный ветер и учесть его
в совете о прогулке. Время можно описывать гибко, например «ранним утром»
или «после дождя», с учётом почасового прогноза.
Модель получает числовой и почасовой прогноз; ей запрещено придумывать
погодные условия, мероприятия и места. При отсутствии ключа, ошибке API
или неподходящем ответе используются готовые комментарии из приложения.

## Настройка OpenAI

Для workflow `.github/workflows/weather.yml` добавьте в настройках репозитория
**Settings → Secrets and variables → Actions**:

- Secret `LLM_API_KEY`: ваш ключ OpenAI API. Значение не добавляйте в код или логи.
- Необязательную repository variable `LLM_MODEL`: модель с поддержкой Chat
  Completions и JSON mode. По умолчанию используется `gpt-4.1-mini`.

Workflow уже передаёт эти настройки приложению. Пустое значение `LLM_MODEL`
также использует модель по умолчанию. Для локального запуска экспортируйте
`LLM_API_KEY`; поддерживается и уже заданный `OPENAI_API_KEY`.
Файл `.env` автоматически не загружается.

В облачной среде Codex задайте ключ через настройки секретов среды с именем
`LLM_API_KEY` и разрешённым HTTPS-доменом `api.openai.com`.
Не используйте `OPENAI_API_KEY` для новой привязки в настройках Codex:
префикс `OPENAI_` зарезервирован платформой. GitHub Actions и Codex имеют
отдельные настройки секретов.

Выполняется один запрос на публикацию, без автоматических повторов,
с сетевым таймаутом 15 секунд. Один абзац ответа ограничен 180 символами
(единицами UTF-16 для лимита Telegram).
Ответы с цифрами, более чем двумя предложениями или без обязательных слов
«сильный ветер» при ветре от 30 км/ч отклоняются и заменяются готовой фразой.
При сильном ветре резервный комментарий тоже сохраняет его упоминание,
даже если основной сценарий дня — дождь, снег или холод.
Результат используется для всех каналов. При ошибке отправка продолжится
с готовой фразой. Успешность генерации реальными моделями и качество советов
нужно отдельно проверить с вашим API-ключом; доступ к конкретной модели
зависит от проекта OpenAI. Запросы расходуют API-баланс.

## Проверка без рассылки

Python 3.11; зависимости закреплены в `requirements.txt`.

```sh
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
```

Тесты имитируют OpenAI, WeatherAPI, Telegram и MAX: реальные запросы
и сообщения не отправляются. Они проверяют генерацию и ошибки ответа,
резервные комментарии, один вызов генератора и ограничения подписи фото.

Для проверки реального GitHub Actions Secret запустите отдельный workflow
**Actions → LLM preview without publishing → Run workflow**.
Он проверяет четыре искусственных прогноза, обращается только к OpenAI
и выводит комментарии, их длину и HTTP-статусы в лог. Telegram и MAX
не вызываются. Неудачная генерация делает проверку неуспешной, без подмены
готовой фразой. Выполняется четыре оплачиваемых API-запроса без повторов.
Локальная команда с настроенным ключом: `python preview_weather_advice.py`.

Полный запуск `app_zngrd_weather.py` сразу публикует сообщения. Для него
по-прежнему нужны `TELEGRAM_BOT_TOKEN`, `WEATHER_API_KEY`, `MAX_BOT_TOKEN`,
`MAX_CHAT_ID`, `MAX_NEWS_CHAT_ID`. Не импортируйте приложение для обычной
проверки: оно исполняется на уровне модуля. Сам модуль `weather_advice.py`
можно импортировать без отправки сообщений.
